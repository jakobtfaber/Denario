# High Severity Issues - Denario Docker Code Review

## 1. Log Injection Vulnerabilities (CWE-117, CWE-93)

**Files:** `/data/denario-docker/proxy/app.py` (lines 174-175, 253-258, 276-277)

**Issue:** User-provided inputs are logged without sanitization, allowing attackers to manipulate log entries.

**Affected Code:**
```python
# Lines 253-258
logging.info(
    f"Forwarding /v1/{path} model={body.get('model')}" +
    (f" (from {model_before})" if model_before and body.get('model') != model_before else "") +
    f" stream={bool(body.get('stream'))} keys={list(body.keys())}"
)

# Lines 174-175, 276-277
logging.warning(f"Upstream {resp.status_code} at {url}; model={(json_body or {}).get('model')} keys={list((json_body or {}).keys())}")
```

**Fix:** Sanitize user inputs before logging by removing/encoding newline characters and limiting content length.

## 2. Generic Exception Handling (CWE-396, CWE-397)

**Files:** `/data/denario-docker/proxy/app.py` (lines 176-177, 238-239, 371-372)

**Issue:** Broad `except Exception: pass` blocks hide error conditions and make debugging impossible.

**Affected Code:**
```python
# Lines 176-177, 238-239, 371-372
except Exception:
    pass
```

**Fix:** Replace with specific exception types and add logging:
```python
except (json.JSONDecodeError, ValueError) as e:
    logging.exception('Configuration parsing error: %s', e)
except ImportError as e:
    logging.warning('Optional dependency unavailable: %s', e)
```

## 3. Streaming Response Context Manager Issue

**Files:** `/data/denario-docker/proxy/app.py` (lines 110-113)

**Issue:** Nested function captures `resp` from async context manager but uses it outside the context, potentially causing connection closure before streaming completes.

**Affected Code:**
```python
async with client.stream(method, url, headers=headers, content=data) as resp:
    def iter_bytes():
        for chunk in resp.iter_raw():  # resp used outside context
            yield chunk
    return StreamingResponse(iter_bytes(), ...)
```

**Fix:** Restructure to ensure context manager remains open during streaming or handle connection lifecycle properly.

## 4. Missing Error Handling for Critical Operations

**Files:** `/data/denario-docker/start.sh` (lines 27-28)

**Issue:** Fallback directory creation lacks error handling - script continues without validation if creation fails.

**Affected Code:**
```bash
mkdir -p "$DENARIO_RUNTIME_DIR"
```

**Fix:** Add error checking after directory creation:
```bash
mkdir -p "$DENARIO_RUNTIME_DIR" || {
    echo "Error: Failed to create runtime directory $DENARIO_RUNTIME_DIR" >&2
    exit 1
}
```

## Recommended Actions

1. **Immediate:** Implement input sanitization for all logging statements
2. **High Priority:** Replace generic exception handling with specific exception types and proper logging
3. **Critical:** Fix streaming response context manager issue to prevent connection problems
4. **Essential:** Add proper error handling for all critical file system operations

These issues pose security risks and operational reliability problems that should be addressed before production deployment.
